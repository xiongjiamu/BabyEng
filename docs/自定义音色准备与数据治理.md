# 自定义音色准备与数据治理

状态：**方案草案，尚未批准采集或训练**  
适用范围：单家庭、本地优先、仅采集有完整授权能力的成年母亲声音；不采集或训练幼儿声纹。

## 1. 为什么现在不直接加“训练音色”按钮

现有跟读录音是幼儿针对单词或短句的零散尝试，文本覆盖、音质、说话人和授权目的都不满足训练数据集要求。Piper 当前维护已经迁移到 `OHF-Voice/piper1-gpl`；官方训练流程要求逐条音频与准确文本组成 CSV，并建议从现有 checkpoint 微调，最后导出 ONNX 与配套 JSON。训练依赖 PyTorch Lightning，而不是当前轻量 TTS 容器里的运行时能力。

- 当前官方训练说明：[OHF-Voice Piper Training](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/TRAINING.md)
- 当前项目及 GPL-3.0 许可证：[OHF-Voice/piper1-gpl](https://github.com/OHF-voice/piper1-gpl)
- 官方音色说明提醒逐个检查模型卡许可证：[Piper Voices](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/VOICES.md)

因此，本阶段只确定采集、授权、删除和训练资源边界，不上传家庭声音、不启动训练，也不把“能录一段音”宣称为“能生成可用音色”。

## 2. 建议的首轮采集方案

以下数字是 BabyEng 的**内部试采起点**，不是 Piper 官方保证的最低数据量：

- 说话人：一名成年母亲；明确排除孩子、访客及背景中可识别的其他说话人。
- 语言：`en-US` 英语提示词；逐条照稿朗读，文本必须与实际发音一致。
- 首轮目标：120 条提示词、人工筛选后 20～30 分钟可用净语音；另留至少 10 条不参与训练的试听句。
- 单条建议：2～8 秒，句首句尾保留少量静音；保持同一房间、麦克风距离和自然音量。
- 质量拒绝条件：削波、持续噪声、明显混响、漏词/改词、其他人声、过度表演或与目标英语口音不一致。
- 存储格式：采集原件保留原始容器；进入训练前统一生成单声道 22,050 Hz WAV 派生文件，并保留原件与派生文件的对应关系。转码文件不能覆盖原件。
- 人工门禁：每条确认“文本一致、说话人正确、无第三方声音、音质可用”；未审核条目不得进入训练清单。

如果首轮试听无法稳定保持身份相似度、清晰度和英语可懂度，应增加或重录数据，而不是通过延长 epoch 掩盖数据问题。

## 3. 授权边界

采集前必须由成年说话人本人完成一次独立授权，记录授权版本、姓名、时间和以下结论：

1. 确认自己是录音中的成年人，并有权授权该声音。
2. 知道模型可以合成本人未实际说过的内容，存在冒用风险。
3. 当前用途限定为本家庭 BabyEng 的本地英语教学，不公开发布、不分享模型、不用于身份验证或代替本人表态。
4. 当前不允许把录音、训练缓存或模型发送到云端；未来若使用外部 GPU/云训练，必须重新取得单独授权并明确服务商、地区、保留期和删除能力。
5. 可以随时撤回；撤回后停止新合成，并进入完整删除流程。

授权不能与普通使用条款合并成默认勾选，也不能由家庭中的另一位成员代替说话人确认。

## 4. 删除流程

未来实现时，数据应按 `family_id/dataset_id` 隔离为原始录音、训练派生数据、checkpoint/日志、已导出模型和该音色生成的缓存。删除必须由已登录家庭用户输入明确确认文本 `DELETE_CUSTOM_VOICE` 触发，并完成：

1. 立即解除家庭音色绑定，回退到内置 Piper 音色。
2. 删除原始录音、转码音频、文本清单、训练缓存、checkpoint、ONNX/JSON 模型和该自定义音色的合成缓存。
3. 删除对应数据库元数据和授权记录的内容副本；仅保留不含声音、文本和模型的删除审计摘要。
4. 显示备份影响：现有离线备份不会被暗中改写，恢复旧备份可能让数据重新出现；必须记录备份轮换/销毁日期，并在恢复时再次执行删除请求。
5. 任一步失败都不得向用户宣称删除完成；返回统一 JSON 错误并列出尚未删除的范围。

“清空全部学习数据”在自定义音色上线后也必须覆盖上述所有目录和绑定；在此之前不得开放采集入口。

## 5. 训练资源与许可证决策

- 当前家庭服务器是运行环境，不承担训练。训练使用隔离工作站，训练完成后只把通过审核的 ONNX 与 JSON 导回本地服务。
- 官方文档提到社区有 8 GB VRAM 成功案例，但官方主要训练资源是 24 GB/48 GB GPU，旧版示例也指出 batch size 32 与 24 GB VRAM 相匹配。因此建议先用 **≥8 GB VRAM 做小批量可行性试验，优先 24 GB VRAM 完成正式微调**；实际 batch size 由最长句与显存实测决定。
- 首选现有 `medium` checkpoint 微调；checkpoint 的模型卡许可证必须单独审核。训练器现为 GPL-3.0，是否随 BabyEng 分发训练环境、以及导出模型的发布方式，需要在实现前完成许可证评审。
- 训练环境不得挂载生产 SQLite、孩子录音或无关家庭数据，只接收已授权的数据集副本；训练日志不得记录录音原文之外的家庭身份信息。

## 6. 开发放行条件

只有 `npm run custom-voice-readiness -- --verify <清单>` 通过后，才可以进入采集页面开发；真正开始训练还需同时具备：

- 成年说话人授权完整且未撤回；
- 采集与删除方案由家庭所有者明确批准；
- 独立 GPU 型号/显存已填写并实测可用；
- 训练器与 checkpoint 许可证已审核；
- 数据集逐条质检、训练/留出集隔离和删除演练均已有证据。

准备度清单只证明决策字段完整，不证明音色质量、授权持续有效或删除演练已经执行。任何一项真实状态变化都应重新校验。
